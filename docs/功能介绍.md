# TG 自动广告机器人功能介绍

**中文** · [English](en/features.md)

机器人：[@KunKunGuangGaoBot](https://t.me/KunKunGuangGaoBot)。私聊发送`/start`开始，系统管理员为100000001、100000002。所有业务和管理操作在Telegram内完成，不提供网页后台。

## 普通用户功能

| 功能 | 当前实现 |
| --- | --- |
| 目标频道/群组 | 批量输入用户名、链接、Chat ID；底部选择器选择私密频道/群组；双方管理员核验、重新检测、测试消息30秒删除、解绑 |
| 发布内容 | 文字、单张图片、视频、动画、文档；保存Telegram原生格式及会员表情实体，支持纯文本/HTML/MarkdownV2；私聊预览后确认 |
| 内容版本 | 编辑建立新版本；历史版本预览；软删除保留引用和日志；已创建发布事件使用独立快照 |
| 广告按钮 | URL按钮；同排多按钮与换行；primary蓝、success绿、danger红；直接解析消息中的会员表情或显式emoji ID |
| 来源消息 | 独立来源授权；展示真实收到的消息；已授权已知消息链接尝试官方复制/转发；复制可带按钮，原生转发保留来源归属 |
| 定时轮播 | 多内容A→B→C循环、多目标；整数分钟/H:MM间隔；有限次数或无限；任务先保存草稿，再确认启动 |
| 即时同步 | 来源新消息独立排队，与定时发布串行处理；事件去重、来源循环检测；即时事件不推进定时轮播游标 |
| 删旧发新 | 按所属用户、任务和目标保存上一条成功消息；仅处理本任务记录的消息；删除失败继续或暂停可选 |
| 任务控制 | 启动、暂停、恢复、停止、立即发布、编辑、移除即时来源、删除；暂停保留剩余等待；重要操作二次确认 |
| 统计与记录 | 个人时区今日统计、任务状态、发送/删除结果、错误、可用公开消息链接；CSV分批导出 |
| 个人设置 | IANA时区、使用教程、联系管理员 |

## 系统管理员功能

- 全局用户、活跃/新增、封禁、任务及投递队列统计。
- 按ID、用户名、名称、状态和最近活跃日期查找用户。
- 查看所有用户的目标、来源、内容、任务与日志；管理行为保存审计记录。
- 封禁原因和二次确认；封禁暂停运行任务、失效向导会话；解封不自动恢复。
- 白名单系统配置：最小间隔、任务/目标/绑定配额、即时队列、测试文案、欢迎语、教程和联系方式。
- 广播支持正文及单条媒体、格式、会员表情、彩色/图标按钮和保护内容。管理员直接发送带会员表情的消息即可，程序保留实体，无需先抄emoji ID。
- 广播先私聊预览，明确确认后建立SQL任务；20格实时进度、成功/失败/跳过/待处理/未知数量；刷新、暂停、继续、取消、失败/未知导出。

## 持久化和可靠性

- PostgreSQL保存用户、绑定、来源、内容版本、任务、会话、发布快照、逐目标投递、广播接收者、消息及审计记录。正文和版本不自动过期；媒体保存Telegram file_id。
- 每个用户的数据按owner隔离，共享频道的删除指针按任务隔离；同一物理聊天共享限速。
- 机器人接收进程先将Telegram updates持久化，再处理；Worker独立执行任务。服务崩溃或系统重启后依据SQL恢复。
- 多目标部分成功时，已经成功的目标不自动重复；明确失败按策略处理，重试遵守Telegram retry_after。
- 网络结果不确定记为UNKNOWN，暂停相应链路，用户人工核对后明确重发或跳过。Telegram和SQL不能实现同一个事务，不承诺外部绝对只发一次。
- 接收与Worker跨进程共享免费发送额度，不启用Stars付费广播。
- 提供SQL备份、空库恢复及健康检查工具，两个服务开机启动、失败自动重启。

## 授权及平台边界

首次绑定必须验证用户和机器人均为管理员。按已确认规则，之后解绑或用户失去管理员身份**不会停止已有任务**；需要用户主动暂停/停止，或在任务中明确移除来源/目标。机器人自身权限不足时仍会失败并记录。

会员表情和按钮图标按发送场景、Telegram资格及客户端实际显示决定；只有明确的自定义表情资格拒绝才兼容降级，其他API错误和未知网络结果不会伪装成成功。菜单九类图标均通过真实Telegram图标集核验。

本版处理单条媒体，相册为扩展项。Bot API不支持任意历史枚举；不使用用户账号Session、短信验证码、非官方协议或绕过保护内容。

免费发送有全局和每聊天限制：10000个目标即使只按20次/秒计算也至少8分20秒，实际更久；最小一分钟间隔不能等同于一分钟发完所有目标。
