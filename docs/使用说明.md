# TG 自动广告机器人使用说明

**中文** · [English](en/usage.md)

## 开始与安全边界

私聊机器人发送 `/start` 或 `/menu`。全部业务在机器人内完成，不提供网页后台。`/cancel` 返回首页并作废当前会话，`/help` 打开教程，系统管理员可用 `/admin`。

菜单和操作记录永久保存在 PostgreSQL。向导会话保存15分钟，进程重启后可继续未过期步骤；超时、取消、返回首页或切换功能后应重新开始。菜单回调绑定操作者ID，不能通过转发别人的菜单操作别人的资源。

用户只能访问自己的目标、来源、内容、任务和日志。系统管理员的跨用户查看和修改进入审计日志。被封禁用户的业务请求静默忽略，运行任务暂停；解封后不会自动恢复任务。任何客户端结果都以数据库日志和实际 Telegram 响应为准。

## 绑定目标频道与群组

1. 将自己与机器人均设为目标管理员。频道还必须授予机器人发帖权限。
2. 打开“目标频道 / 群组 → 新增”，点击底部频道/群组选择器可选择私密目标，也可每行输入一个 `@用户名`、`https://t.me/用户名` 或数字 Chat ID，每批1至100个，可分批重复提交。选择器同时要求双方管理员权限，返回的Chat ID仍需经过服务端重新核验；来源绑定也支持相同选择器。
3. 机器人实时检测双方权限并逐项返回频道、群组成功数及失败原因。普通用户、无效链接、邀请链接、非管理员、机器人无发帖权限不会绑定成功。
4. 目标详情支持重新检测、测试消息和解绑。测试会真实发送，成功后创建30秒删除计划，删除是否成功请看日志。生产验收前不要对无关目标点击测试。

首次绑定同时验证用户与机器人管理员身份。绑定后用户离开或失去管理员身份、从菜单解绑目标，都不会自动停止既有任务；解绑仅使目标不再参与新的任务选择。机器人自身权限不足则无法发送，任务错误会被记录。需要停止发布时必须明确暂停/停止任务，或暂停后编辑任务移除目标。

## 保存发布内容

在“发布内容 → 新增”输入标题，再发送文字、单张图片、视频、动画或文档。收到的正文、caption、Telegram entities、custom emoji ID 与媒体 file_id 保存为版本。

格式可选择：收到的原生实体、纯文本、HTML、MarkdownV2。选择 HTML 或 MarkdownV2 后不再同时发送 entities，避免格式冲突；语法错误必须修正后重新预览，不会当作保存成功。每次必须私聊预览成功，再点击确认保存。

“编辑新版本”生成新版本，不会改写旧版或已产生事件的发送快照。“历史版本”只读预览。“删除”需要二次确认，为软删除，禁止新选择但保留既有引用及历史；请同步检查相关任务。

### 按钮语法

```text
#p 官方网站 - https://example.com
#g 查看活动 - https://example.com/a && #r 联系客服 - https://t.me/example
#p {emoji:5368324170671202286} 查看详情 - https://example.com
```

`#p` 为蓝色，`#r` 为红色，`#g` 为绿色。同一行用 `&&` 分隔按钮，换行建立新行；发送单独的 `-` 清空按钮。支持直接发送带 custom emoji entity 的会员表情，或显式填写 `{emoji:数字ID}`。按钮链接使用解析器允许的安全地址；非法行会返回行号和原因，不会部分保存。

自定义表情能否发送仍取决于 Telegram 当前资格和权限。只有明确的表情资格错误才会尝试降级为原文字，并记录降级状态；模糊的网络错误不会被伪装成表情不支持，也不会盲目重试。机器人不会随机构造 emoji ID。菜单图标无有效配置时使用明确的普通 emoji 默认值；Telegram明确拒绝自定义图标资格时，菜单移除图标ID、保留颜色样式，最多重试一次并记录审计。菜单、私聊预览、测试及CSV发送统一调用引擎限速器。

## 消息来源与历史限制

来源和目标分别绑定，首次授权同样检查双方管理员权限。在“消息来源”中查看机器人实际收到并保存的消息索引，选择某条导入内容，或在内容列表输入来源消息链接。

Bot API 不能枚举任意历史，来源索引只展示机器人实际收到的消息。对于已知的消息链接，先验证来源曾被当前用户授权，再使用官方复制/转发API在私聊尝试预览；即使机器人此前未保存此条索引，也不先断言必然无法复制。访问权限、保护内容、消息删除等仍可能导致失败，以真实API响应为准，不会用假消息替代或声称已读取。

导入后选择“复制”或“转发”。复制保留正文/媒体，可添加按钮；转发保留来源归属，不支持自定义按钮。保护内容或 Telegram 限制可能导致复制/转发失败，应以预览结果为准。

来源解绑仅隐藏新选择，不会自动解除既有任务的即时监听。真正停止即时来源须在任务详情点击“确认移除即时来源”，或停止/删除任务。

## 创建与管理任务

在“轮播任务 → 新增”完成向导：名称 → 多条内容 → 多个目标 → 间隔 → 删旧及失败策略 → 可选即时来源与复制/转发模式 → 最多轮次 → 预览确认。内容按点击顺序排列；全选按列表ID顺序。内容和目标均支持分页、全选与清空，目标数量受配额限制。

间隔输入整数分钟或 `H:MM`，例如 `50` 为50分钟，`1:30` 为90分钟。最低60秒，可由管理员提高。最多轮次为 `0` 表示无限。保存任务只建立草稿，不会自动向目标发送，必须在详情点击启动并再次确认。

- 启动/恢复：恢复暂停时保留剩余等待，不把间隔重算为完整一轮。
- 暂停：停止调度后续发布，保存剩余等待；已经在途的请求仍可能返回结果。
- 停止：停止当前任务链路；历史日志不删除。
- 立即发布：通过调度引擎创建事件，不绕过数据库状态和权限检查。
- 编辑配置：仅草稿、已暂停、已停止或已完成状态；有未完成事件须先处理或停止。调整目标保留历史记录。已完成任务编辑后转为停止并重置完成轮次，必须再次主动启动。
- 删除任务：二次确认并软删除，历史、消息和审计仍保留。
- 发送前删旧：先处理上次对应消息，再发本轮；删除失败默认继续并记日志，也可选择删除失败暂停。
- 失败跳过：由引擎根据任务策略处理明确失败，不把不确定结果擅自当成失败重发。

即时来源的新消息与定时任务由引擎统一调度、排队并保存快照。来源循环、非法跨用户引用、超额目标和无效状态会被拒绝。UI遇到Telegram `RetryAfter` 时会更新所有实例共享的冷却时间，并提示稍后重试，不自动重发原业务操作；未知网络结果同样不自动重试。

### UNKNOWN 处理

网络中断或进程异常可能使 Telegram 已收到消息，但机器人不知道结果，此时标记 `UNKNOWN`。数据库与 Telegram 无共同事务，无法保证外部发送绝对不重复。

先人工检查目标实际消息，再选择“UNKNOWN重发”（可能重复）或“UNKNOWN跳过”（可能漏发），均需二次确认。不要反复点击立即发送代替确认。服务重启不会无条件重发不确定请求。

## 统计、日志与个人设置

“发送统计”显示用户当前时区的今日发送/删除状态、任务状态分布、绑定数与最近错误。消息记录分页展示操作、状态、Chat ID、错误和可构造的公开消息链接；私有消息或无用户名目标不伪造公开链接。

CSV导出逐批读取，每份最多10000行，包含发送与删除结果及内容版本。单元格对公式前缀做转义，避免在表格软件打开时执行公式。导出只发给请求者本人；管理员可从用户详情导出指定用户数据。

在“个人设置”保存 IANA 时区，如 `Asia/Shanghai`、`Europe/London`；这影响用户今日统计边界。任务调度时间由数据库 UTC 时间管理。联系管理员与使用教程可从首页打开。

## 系统管理员

默认系统管理员ID为 `100000001`、`100000002`，并可按部署配置增加管理员。管理入口仅向管理员开放；普通用户构造 callback 不能获得管理权限。

总览显示用户总数、今日新增、24小时活跃、封禁数、运行任务、待处理/未知队列、目标类型数与服务器当日操作统计。用户可按ID、用户名、名称、`ACTIVE`/`BANNED` 搜索；最近活跃时间范围语法为 `seen:YYYY-MM-DD:YYYY-MM-DD`，范围按UTC日期解释，最多展示50条，请缩小查询条件。

用户详情提供基本资料、首次/最近活动、资源数、封禁原因及其目标、来源、任务、内容、日志。封禁必须输入原因并确认，同时暂停运行任务、使会话失效；解封只解除封禁，不自动启动。系统管理员不能通过此UI被封禁。

“全部任务”“全部内容”“全部目标”可跨用户查看和操作，均审计。系统配置仅允许白名单键：最低间隔、任务/目标/绑定配额、即时队列上限、测试文案、欢迎语、教程和联系方式；修改有类型范围校验、二次确认和前后值审计，不能通过菜单读取或修改 Token、数据库密码。

### 广播

1. “管理员 → 广播 → 新增”，发送正文/媒体，设置格式、按钮及保护选项。
2. 只先发送到管理员私聊预览，不会因为预览而广播。
3. 点击“确认广播”才创建真实广播任务，接收用户由引擎按当前资格筛选。确认会话使用SQL原子消费，重复/并发确认不会建立两次相同会话广播。
4. 详情显示20格进度、完成率、成功/失败/跳过/待处理/UNKNOWN、最近失败原因；支持刷新、暂停、继续、取消未发送项及失败/未知明细CSV。
5. 取消不会撤回已经成功发送的消息，在途发送仍可能完成。UNKNOWN须人工确认重发或跳过，处理后广播处于暂停状态，检查后再点击继续。

广播是生产操作，本项目自动测试只使用假对象，不会读取Token、启动机器人或向真实用户广播。正式验收应先使用独立测试机器人、隔离数据库和少量自有测试账号，再由管理员明确确认生产广播。
