# 测试与验收报告

**中文** · [English](en/acceptance-report.md)

本文记录本项目的自动化测试覆盖、SQL 容量烟测和真实 Telegram 验收的**实际范围**，包括哪些已验证、哪些没有验证。开源仓库保留这份报告的目的，是让使用者能准确判断自己可以依赖什么。

验收环境：Ubuntu 24.04 / Python 3.12 / python-telegram-bot 22.8 / PostgreSQL 16，长轮询接收服务 + 独立持久化 Worker，无 Web 后台。演示机器人：[@KunKunGuangGaoBot](https://t.me/KunKunGuangGaoBot)。

## 架构验收

两个 systemd 服务均开机启动、失败自动重启，使用 SQL advisory lock 阻止同角色双实例：

| 服务 | 职责 | 启动方式 |
| --- | --- | --- |
| `tg-auto-ad-bot.service` | 持久化 updates、用户交互、来源摄取 | `python -m adbot.main` |
| `tg-auto-ad-worker.service` | 轮播、即时事件、逐目标发送、广播进度 | `python -m adbot.worker` |

PostgreSQL 仅监听本机，不开放公网；接收服务不在本机监听任何 Web 端口。进程存活不等于业务正常——**发送链路可能在使用进程仍存活时出现 `ConnectTimeout` 或 TLS `Hostname mismatch`**，因此本项目提供健康检查脚本，用接收/Worker 心跳判断真实可用性，而不是只看 `systemctl status`。

## 本地容量烟测

在隔离 SQL 环境生成 2000 用户、10000 个聊天与绑定、2000 个运行中任务（每任务 5 目标）：

| 测量项 | 结果 | 说明 |
| --- | --- | --- |
| 20 批调度（每批 100 任务） | 6.662 秒 | 生成 2000 事件、10000 条投递记录，无漏关联、无重复调度 |
| 该 schema 体积 | 约 9.92 MiB | 含连表、TOAST 与索引；仅为该样本，不是长期空间预测 |
| 10000 条未来重试记录下的新任务调度 | 0.097 秒 | 已就绪任务在首个 tick 仍能被服务 |
| 2000 个任务全部恢复后的轮转 | 63 tick / 9.559 秒 | 每个任务在 63 次 tick 内至少被服务一次 |

这些数字跳过真实网络等待，只证明 **SQL 完整性、调度公平性和索引设计**，**不等于**真实 Telegram 万人压测、长时间稳定性验证或吞吐 SLA。

## 真实 Telegram 验收范围

实发范围只限两位已配置的管理员私聊，不向生产用户或频道群组批量测试：

1. 主菜单：两位管理员各收到 9 个按钮、9 个按钮图标，Telegram 返回结构与预期一致。
2. 带会员表情与三色按钮的消息：Telegram 返回 1 个 `custom_emoji` 正文实体和 3 个按钮，`primary` / `success` / `danger` 均保留，`degraded=false`。
3. Worker 隔离库实发轮播：连续两轮发送，第二轮前 `deleteMessage` 成功删除第一轮消息，SQL 依次记录 `SEND SUCCESS` / `DELETE SUCCESS` / `SEND SUCCESS`，达到设定次数后任务转为 `COMPLETED`。
4. 单接收者广播：`total=1, success=1, failed=0, unknown=0`，状态 `COMPLETED`，进度消息由 Worker 动态编辑成功。
5. 菜单图标来自真实 HandEmoji 图标集：官方示例 seed 加批量 `getCustomEmojiStickers` 核验后写入 SQL，共 9 类，无伪造 ID。

**没有验证的部分**（请勿假定已验收）：

- 频道 / 群组的真实管理员权限组合与所有媒体场景——需要自行绑定测试目标后按[使用说明](./使用说明.md)用「测试」按钮验收。
- 跨客户端视觉差异（动画、会员表情渲染）取决于 Telegram 客户端，API 返回实体不代表所有客户端显示一致。
- 真实万人广播、长时间稳定性压测。

Worker 私聊诊断脚本仅在随机 schema 中运行，并只为该已知管理员私聊替换了目标校验，未改动生产权限逻辑。

## 启动行为

接收服务启动时向每位管理员各尝试发送一条 `已启动` 通知，内容包含接收服务状态与 `/start`、`/admin` 入口。**启动不会新建广告任务，也不会向全体用户广播**：已确认启动的任务和广播按 SQL 状态继续，残留的不确定请求进入 `UNKNOWN` 等待人工核对。

## 已知边界

- 免费发送受 Telegram 限速：全局约 20 次/秒，同群约 3.1 秒间隔。10000 目标仅理想全局发送下限就约 8 分 20 秒，权限查询、删旧、媒体与网络都会再增加耗时；**不能把「最小 1 分钟间隔」理解成一分钟发完 10000 个目标**。
- 任务的「完成一次」指选中一条内容向本批目标投递完成，之后游标移到下一条；A→B→C 一整圈算三次。即时事件不增加该计数。
- 多目标部分失败时，成功的目标不会自动重发；`UNKNOWN` 需人工核对后选择重发（可能重复）或跳过（可能漏发）。Bot API 没有业务幂等键，**不承诺对外部绝对 exactly-once**。
- 会员表情资格按实际发送场景判断，私聊验收不自动证明频道也获准；只有明确的资格拒绝才降级，未知网络错误不会伪装成成功再发一次。
- Bot API 无法枚举任意历史，保护内容等限制不能绕过；转发不支持附加自定义按钮。
- 本版一次处理一条媒体，相册为后续扩展项。
